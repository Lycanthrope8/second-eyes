## 2. Final configuration

Policy `iref.order.crossed_cyclic.v1`. For n objects and letters C[0..n-1]: object O[i] gets C[(i + a) mod n]; list
position j shows O[(j + p) mod n]; K (ASK) last; every (a, p) in 0..n-1. Variant IDs `qNNN.aAA.pPP`. Schedule: identity
cells first in base order, then SHA-256 of UTF-8(`second-eyes/a23c/order/v1` + LF + variant ID), ties by ID. Canaries:
the first base request's (0, 0), (1, 0) and (0, 1), atol = rtol = 1e-5, same code and object. Repeat controls:
`|new - old| <= 1e-5 + 1e-5 * |old|` for every offered logit, same code and decoded object or ASK. Context limit 8,192
with the one-token continuation. Pins: selected parents `8c826ba3…`, r003 `results.jsonl` `7e558382…`, A2.3b summary
`9a7231ae…` and report `b3e56936…`. Expected population: 128 bases, 4,536 cells (n = 3..10 for 8, 22, 26, 34, 20, 14,
2, 2 bases; 3,004 full-inventory and 1,532 source-known cells).

## 5. Decisions taken

D94 (the brief's design, adopted as written). Implementation choices disclosed: prompts and token IDs stored as one
JSONL file per base request (`variants/qNNN.jsonl`) rather than 9,072 files; three-way crossing kept intact by

## 6. What failed and why

- A test expectation of mine was wrong, not the code: for a responder that follows list position 2 except in cell
  (1, 0), I first expected 6 list-shift changes. Re-derived by hand: (1, 0) is its row's reference and now equals
  (1, 1), so the row contributes 1 change and the total is 5 of 6. The test was amended with the derivation.
- The rehearsal found a real defect: the score report's rows followed dictionary order, which JSON's sorted keys
  change, so the readback's re-rendering differed. Rendering now uses a fixed view and format order and numeric
  position order.
- Every readback validated each variant line's thousands of token IDs through jsonschema, which dominated the run
  time (the file-chain test took 216 s, 162 s of it in reading variant lines). Those lines are now checked directly
  by the same rules (exact keys, a string prompt, plain non-negative integer token IDs); the suite takes about 20 s,
  and a float token ID is a new tamper case.
- The model description's bytes: the sandbox reconstruction of the base requests had pinned a CRLF copy (`bf1e8db8…`),
  and this note first said the real requests did too. Corrected on acceptance: the real requests pin the laptop's file,
  `57ad40a0…` (LF), as the laptop's `prepare` run confirmed. Either way the RTX PC must be given the exact pinned file,
  which the transfer package carries.

**Findings (descriptive).**
- Strong answer-code sensitivity. When only the letters are reassigned, the chosen object changes in 92–97% of pairs
  (macro), and the same letter is chosen again in 66–89%.
- Additional choices-list order sensitivity. When only the list order changes, the chosen object changes in 11–34% of
  pairs, while the same list position is kept in only 2.2–8.5%.
- Full-grid agreement with the annotated targets stays close to the always-B reference in every view and format.
- The identity cells' agreement (8 to 11 of 32) holds under list-order shifts (0.25–0.29 macro) but falls under letter
  reassignment (0.12–0.21 macro in the assignment-only and crossed cells).

**Limits.** The research sample is 32 parent commands from one inspected room; the 4,536 variants are repeated
measurements of those commands, not independent examples. The scene document, its object order and its IDs were fixed.
No format winner, no general grounding-accuracy claim, no headset-readiness claim and no Gate B conclusion follows.

**Closed.** A2.3c is closed without further ordering experiments. The remaining A2.3 work follows: a three-system
comparison on 256 more commands with one frozen, answer-blind code and list order per parent and view (A2.3d), then the
cost, cache and perspective checks and A2.3's closure (A2.3e).
