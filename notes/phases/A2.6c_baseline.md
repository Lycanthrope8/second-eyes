## 2. The parts (`grounding/inference/iref_vla_dev/`)

**`preflight.py`** is read-only. It checks:

- both frozen hashes, and every preparation-manifest hash except `reference_only/`, which it never opens;
- the index against the request file;
- unique IDs, the ID rule, four-way coverage, and the parents equal to the sampling's;
- each request against its scene's A2.2d bundle:
  - its derived IDs;
  - its document, equal to the bundle's rendered document;
  - the D104 mapping, recomputed from the derived scene with the pinned protocol;
- the prompt, rebuilt from the document and the mapping (hash and bytes);
- the token hash and count, the context limit, and both token boundaries;
- each model's own pinned tokenizer: its token IDs and A2.3d's offered-letter boundary check.

It refuses with diagnostics, and writes a receipt with identities, versions and code hashes. `context_for` builds A2.3d's
runner context from a passed preflight.

**`runs.py`, the models.** A2.3d's accepted `smoke` and `run_compare` run unchanged:

- float32, eager attention, evaluation mode, batch one;
- one uncached final-position forward;
- the existing TF32 and determinism settings;
- the canaries (the first and the longest request, on the independent path);
- the settings frozen by the smoke record;
- the run lock, which resumes only on identical inputs, checkpoint, settings and code;
- every request kept with its status (`completed`, `context_budget_exceeded`, `execution_failed`).

The one change to accepted code: `smoke` and `run_compare` take an optional context and an optional results readback.
Without them, A2.3d is unchanged, and its suite still passes 59 of 59.

**`runs.py`, the rules.** A2.3d's rules sequence, through A2.3b's baseline module, runs per scene bundle in non-sample
mode:

- `join` re-verifies each entry, including that the request's document is the bundle's rendered document;
- one parse per text;
- one resolver call per parent and view: one observation, shared by both formats.

**`desktop.py`:**

- `export`, on the RTX PC: the 64 frozen requests, with A2.5's replay input fields;
- `run`, on the laptop: A2.5's self-checks, the stderr-captured load and the accepted GGUF, then per request the input
  check with the native tokenizer and path U only;
- `compare`: against the matching new 0.5B float32 rows.

It is labelled a desktop comparison: no Quest agreement, and A2.5's numerical acceptance stays unresolved.

**`score.py`.** The targets are read here only. Each run is read back first.

- The models' outcomes are A2.3d's `outcome_of`: correct, wrong object, ASK (never a technical failure), over the
  ceiling, or execution failure.
- The rules are correct only when resolved to the target. Otherwise they keep their own bins.
- Every parent stays in the denominator.

**`analysis.py`.** For development, per system, view and format:

- command-weighted (N/n per environment and stratum);
- environment-weighted (each environment's eligible relation proportions restored, then equal environments);
- the unweighted stratified sample, labelled.

Each also has command-weighted outcome rates. The bootstrap is paired, by environment cluster:

- `random.Random(20261010)`, B = 10,000;
- environments drawn with multiplicity, the same draws for every system, format and view;
- 95% percentile intervals (Hyndman-Fan type 7), with `math.fsum`.

It reports twenty paired differences, per-relation results, and the coverage table, with "above" and "in" unavailable.
The legacy environment is reported separately, as point estimates. The scope statements come with the results.

## 3. Verification (`grounding/tests/test_iref_vla_baseline.py`, 21 checks; Python 3.11 and 3.12)

**The analysis, on hand-calculable fixtures:**

- 4/7, 1/3 and 1/2;
- an environment drawn twice, giving 2/3 for all three estimators;
- unequal environment sizes, 10/11 against 1/2;
- failures kept in the denominator, with every outcome's rate summing to 1;
- deterministic draws over the sorted environments, with multiplicity;
- the type-7 quantile;
- pairing: two identical systems differ by exactly zero in every replicate.

- **The desktop:** exported, path U, compared and labelled.
- **Scoring:** ASK always comes from a completed forward, and the failed request is scored as such.
