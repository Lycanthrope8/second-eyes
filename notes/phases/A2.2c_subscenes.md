## 6. What failed and why

1. **A shell error while writing the expectations.** A heredoc delimiter mismatch meant nothing was written; the file
   was written correctly on the next attempt.
2. **A test bug, fixed before freezing.** The no-answer test's "permitted reads" check would have flagged the
   manifest's runtime provenance, the installed jsonschema version read from package metadata. It now allows the
   interpreter's own paths.
3. **A name collision.** The accepted package exports its `predict` function under its module's name, so the audit
   imports the two validation helpers from the module directly. No accepted file changed.

## 7. Deviations from the plan

One reading where the brief was in tension. Section 5 hashes the parent scene with the accepted canonical JSON helper,
which keeps array order. Section 8.4 requires that permuting object order changes no row. The audit therefore hashes
the scene with its objects in the brief's own explicit lexicographic ID order. For the pinned sample this equals the
hash of the file as given. The choice is recorded in D77.
