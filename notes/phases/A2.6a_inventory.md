## 1. The release (established)

**Source.** IRef-VLA at the pinned commit `741cf0289a6ee7c8f0763058f40bb3788b76f8e0`, the same commit as A2.2a.

**Distribution.** The repository's `data/download_dataset.py` fetches one zip per source:

- from the bucket `iref-vla`;
- on CMU AirLab's S3-compatible store (`airlab-cloud.andrew.cmu.edu:8080`);
- with unsigned, anonymous requests.

**Terms.** The repository's code is MIT. Each scan dataset keeps its own terms, which are recorded per source before
it is acquired.

**Sources, as the README publishes them:**

| Source | Scenes | Regions |
|---|---|---|
| ScanNet | 1,513 | — |
| 3RScan | 1,381 | — |
| ARKitScenes | 4,494 | — |
| Matterport3D | 90 | 2,195 |
| HM3D | 140 | 1,991 |
| Unity | 15 (3 more withheld for a challenge) | 46 |

**Per scene,** the release has four text files:

- `object_result.csv` and `region_result.csv`;
- `scene_graph.json` and `referential_statements.json`.

It also has `.npy` split indices and a `.ply` free-space cloud. Only the four text files are read; the geometry
files are never read.

**Splits.** The loader reads scene lists, `<split>.txt`, from inside the downloaded dataset. `merge_splits.py`
combines per-source lists (`referit3d`, `3rscan`, `arkitscenes`, `matterport`, `hm3d`, `unity`). The lists themselves
come with the downloads; they are not in the repository.

## 2. Format compatibility (established on the six pinned sample scenes)

The repository carries one scene per source, which gives a multi-source test set at the pinned commit:

- ScanNet `scene0010_01`;
- 3RScan `02b33e01-…`;
- ARKitScenes `47204840`;
- Matterport `5q7pvUzZiYa`;
- HM3D `00238-j6fHrce9pHR`;
- Unity `loft`.

Their 24 text files, 61.5 MB, are pinned by size and SHA-256. The ScanNet statements' pin equals A2.2a's.

**What the six sources share:**

- identical object and region CSV headers;
- the same JSON structure, `{scene_name, regions}`;
- the same statement record keys as v1's;
- `target_class` equal to the object's `nyu_label` in every entry (334, 88, 12,781, 5,490, 1,951 and 2,511 entries);
- statements that are binary (one anchor) or ternary (two anchors);
- no frame or viewpoint field anywhere, so O27 stands.

**Where they differ:**

- **The number of regions.** ScanNet, 3RScan and ARKitScenes have one; Matterport has 19, HM3D 23 and Unity 3 in
  these scenes.
- **Unity's no-region marker.** Unity marks objects outside every region with region `-1` (14 objects in `loft`).
- **One label outside the NYU vocabulary,** in the Matterport scene.

## 3. The versioned extension (`grounding/adapters/iref_vla/release.py`, `iref_vla_release.v1`)

The one-scene adapter (`pinned.py`, `convert.py`) is unchanged, with its pin checks, and A2.2a's suite still passes
(96 of 96 on the pinned sample).

**Shared from v1, not copied:**

- the headers;
- the accepted row widths (whole colour groups may be omitted);
- the statement record keys;
- the strict CSV and JSON readers.

**The extension adds:**

- **The pinned samples:** `fetch-samples` and `verify-samples`.
- **Access:** `probe` (header-only: each zip's size, ETag and date) and `download` (streamed, hashed as it arrives, kept
  only when complete, never overwriting, with a provenance receipt).
- **Reading** from a folder or straight from a source zip, the four text kinds and `.txt` files only.
- **Validation per scene.** A scene is rejected, with a code, for:
  - a scene name that is not the source's;
  - missing files, or the source shape (v1's readers);
  - repeated or non-decimal object IDs, or regions not in the region file (`-1` is the documented exception);
  - non-finite boxes.
- **Exclusion per statement,** with a code, for:
  - the record shape;
  - a target that is missing, or outside the statement's region;
  - a target class that is not the object's `nyu_label`;
  - a missing distractor;
  - a missing anchor, or one outside the region.
- **Counts per scene:**
  - objects, regions and objects without a region;
  - parent texts, entries, and texts with several entries (recorded, not called ambiguous);
  - relation types, relations and anchors;
  - labels outside the vocabulary, and frame annotations (none);
  - an object fingerprint and the input hashes.
- **The compatibility estimate.** A2.2c's own `select` (category-complete, never truncated) runs on the statement's
  annotated categories, the target's and the anchors' `nyu_label`, bucketed by the 3-to-10 range. The accepted
  parser's categories replace these in the preparation (A2.6b).

**Regression.** On the pinned ScanNet scene, the extension reads 1,936 parent texts and 1,951 entries. Every entry's
command ID and target equal v1's converted annotations. The compatibility estimate equals an independent count of the
rule (1,530).

**Tests:** `test_iref_vla_release.py`, 30 checks, run against a pinned-only copy (as `fetch-samples` writes it) and
against the full checkout.

- Access: probe, download, overwrite and a short transfer.
- Fetching samples against their pins.
- The six sources' counts, regions and groups.
- The v1 regression.
- Zip reading equal to folder reading, never touching geometry.
- Official versus other text files, including a scene-folder file whose lines look like scene names.
- Seven refusals and exclusions.
- Fingerprint merging and ancestry metadata.
- The partition proposal.

Without the samples, the sample checks fail rather than skip.

## 4. Groups and partitions (the foundation; nothing frozen)

**Groups by physical environment and ancestry,** each recording how it is known:

| Source | Group | Known |
|---|---|---|
| ScanNet | rescans of one space share `sceneNNNN` | by name |
| Matterport | one building | by name |
| HM3D | one building | by name |
| Unity | one synthetic scene | by name |
| 3RScan | needs the source's reference and rescan metadata | unverified until supplied |
| ARKitScenes | needs the source's video-to-visit metadata | unverified until supplied |

Regions stay with their building or scene. Scenes with identical object fingerprints merge into one group, flagged.
The inspected `scene0010_01`'s series, `scannet:scene0010`, is the **legacy-development** group.

**The partition proposal** (`a26.partition.v1`):

- **Salt:** `second-eyes/a26/partition/v1`, fixed before any selection.
- **Shares:** 70, 10, 10 and 10 by group hash.
- **The legacy group** goes to `legacy-development`.
- **Unverified ancestry** leaves a group unassigned.
- **Official lists are preserved:** a training list gives training; a held-out list goes to development, calibration
  or test, never training; a group in both is a recorded conflict, left unassigned.

A proposal is never frozen by the tool. Its counts are inspected first, then the run specification is frozen before
any inference.

## 5. What remains open

1. **Which sources to acquire,** the bounded subset. `probe` gives each zip's size without downloading it; that, plus
   each source's terms, decides the subset.
2. **Ancestry metadata** for 3RScan and ARKitScenes, if those sources are used. Until it is supplied, their groups stay
   unassigned.
3. **The official lists** in the downloaded zips. The inventory records them, and the proposal applies them.
4. **The exact compatibility count** with the accepted parser (A2.6b's preparation, versioned).
5. **The coverage summary** of target, relation, anchor and frame annotations, for A2.4's direct-selection and parsing
   designs. It is computed from the inventory of the acquired data.
6. **The development caps** for scenes, commands and actual model requests (formats × views × systems), and the compute
   estimate. These follow from the real counts.
