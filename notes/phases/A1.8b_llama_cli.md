## 1. What was built

A small C interface over llama.cpp (`native/se_llama`), a test program run through `adb shell`, the build
(`tools/build_llama.py`, with the NDK inside Unity), the conversion to 8-bit (`grounding/export_gguf.py`), candidate
references from PyTorch (`grounding/reference.py --candidates`), shared scene definitions (`grounding/scene.py`), and
the driver that prepares, pushes, runs and checks (`grounding/llama_headset.py`). D55, D56.

## 2. Final configuration

llama.cpp `b11277` (`eae11d22`), built with NDK 27.2.12479018 (Unity 6000.3.25f1), clang 18, `arm64-v8a`,
`GGML_CPU_ARM_ARCH=armv8.2-a+dotprod+fp16`, OpenMP off. Model `qwen2.5-0.5b-instruct-q8_0.gguf` (531 MB, SHA-256
`dd753cd6`), memory-mapped, context 1024. Runs: PC candidate references `20260930_A1_r026`, answer references
`20260929_A1_r016`, headset `20260930_A1_r027` (worn in Home, after a fresh reboot, plugged in).

## 6. What failed and why

The check's first verdict was FAIL: its log-probability tolerances judged unlikely candidates that 8-bit weights move
most. D56 replaced them. On this machine, the Linux test build crashed once with an illegal instruction after a move to
another processor: native flags, harmless for Android, whose build names its instruction set.
