## 1. What was built

A2.1d had three parts.

1. **The v0.2 token audit** (`analysis/A2.1d_token_sizing/`). It measured the original frequency-default encoding of
   both candidate formats with the pinned tokenizer, on four inputs: a17 annotated and restricted (six objects), and the
   first ten objects of scene.h annotated and restricted.
2. **The indexed audit** (`analysis/A2.1d_indexed_token_sizing/`). It re-encoded the same facts in indexed rows, verified
   decoding against the saved originals, and measured again.
3. **The serializer** (this increment, D69): `grounding/serialization/`, which renders `coordinates_v2` and
   `coordinates_relations_v2` from validated records by calling the accepted relation libraries. It comes with:
   - a strict canonical codec;
   - the work guard, which counts before construction;
   - an optional token-check hook;
   - traceability metadata;
   - a thin offline CLI;
   - fixed goldens and the test `grounding/tests/test_serialization.py`;
   - `docs/serialization.md`.

Not included:
- **Unchanged:** both audit folders, byte for byte, and every accepted library, configuration, schema, fixture and test.
- **Not built:** a resolver, language parsing, an ASK policy, an adapter, training, a tokenizer integration, caching,
  or C#, Unity or headset code.

### The D70 correction: the required category map

**What D70 is.** A clarification approved by the project lead in ChatGPT's correction brief of 3 October 2026, not a
defect found in the delivery.

**What changed.** Until D70, a supplied map collection without the scene's map counted as no map, with only a warning.
Now, in both formats, it raises `E_CATEGORY_MAP_MISMATCH` before configuration loading or rendering. No maps at all
keeps the warning. The check runs only on records the validator accepted, and the shared validator, the goldens and
both audits are unchanged.

**The regression,** written before the guard. The old check that accepted the warning was replaced by:
- ten checks per format;
- a CLI check for a map of another ID;
- a CLI check of exit code 3 under a controlled test exception.

**Before:** run against the serializer as delivered, 161 of 166 checks passed. The 5 failures were the expected ones:
- a map with another ID was accepted, in each format;
- no sorted-ID message, in each format;

## 6. What failed and why

Two errors, both in Claude's tests and both caught before delivery.

**Codec rejection tests passed for the wrong reason.** Four of them built `between` blocks with `conditional` before
`states`. The decoder rejected those blocks for their field order and never reached the row checks: the tests passed
vacuously. The fix rebuilt the blocks in the right order and made every codec rejection test assert its expected reason.

**A test assumed the library's wording.** The cache-conflict test expected the word "conflict" in the library's error.
The library actually says "was reused for different geometry". The behaviour was right; the test now matches the real
message.

## 7. Deviations from the plan

**Configuration hash.** The configuration file's SHA-256 is now taken before and after loading, and a difference is an
error. This keeps metadata from pairing one file's hash with another file's values.

**Codes and exit codes.** The serializer's own error codes are `E_OPTION_*`, `E_RECORD_ROLE`, `E_CONFIG` and
`E_INPUT_FILE`; D70 adds `E_CATEGORY_MAP_MISMATCH`. The CLI's exit code 3 for unexpected internal errors was not
specified by the brief; D70 approves it for an unexpected exception escaping the rendering call.
