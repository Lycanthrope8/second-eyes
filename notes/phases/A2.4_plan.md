## 2. The design in brief (D109)

- **Configurations:** three, with three paired seeds each, nine fits in all.
  - Direct selection in `coordinates_v2`.
  - Direct selection in `coordinates_relations_v2`.
  - A text-only parser writing the v1 semantic language, fed to the accepted resolver.

  The 7B stays A2.6's zero-shot reference.
- **Labels (a positive-reference pilot):**
  - an incompatible view is excluded and reported;
  - no K (ASK) label is trained, and K stays available at inference;
  - annotation, mapping and rule-parser disagreements are quarantined;
  - the rule parser is a diagnostic only;
  - an independent audit of real examples, reviewed by people.
- **Cohorts:** from the frozen training partition.
  - 120 fitting environments and 25 inner-validation environments, plus an ordered reserve.
  - Caps of 9 and 8 per environment; minimums of 900 and 180 parents.
  - Within each environment, the stratum order is salted (A2.4's sampling policy). A2.6's own sampling is unchanged.
- **Selection:** on the inner validation, unweighted over the retained rows. This refines "development guides
  selection". All nine fits finish before any development result is examined.
- **Evaluation:** one complete frozen development evaluation per selected checkpoint, nine in all.
  - Direct: all 10,860 requests, with the trained format primary and the other format as a labelled cross-format
    analysis.
  - Parser: one decode per parent, resolved in both views.
- **Environments and identity:**
  - a separate `.venv-train`; the accepted `.venv` is unchanged;
  - a separate fine-tuned identity beside the unchanged base check;
  - the importer's explicit training mode (`release.TrainingAuthorization`).
- **Docstring:** `analysis.py`'s percentile wording is corrected, which changes A2.6c's code identity. Old receipts
  keep theirs, and A2.4 binds a fresh preflight.

## 4. Stage A (acceptance; then ChatGPT's review)

The runbook is `A2.4_runbook_stage_a.md`. It is delivered beside the zip, because it carries the zip's hash, and Part 1
commits it.

1. **Laptop:** verify the zip, apply it, run the records script, run five test suites, commit and push.
2. **RTX PC:**
   - pull; create `.venv-train` (pinned; `pip freeze` recorded) and run the stand-in training suite;
   - freeze the training specification;
   - prepare: real eligibility counts, labels, cohorts, examples, the audit and `pilot-spec.md`, with UTC start and
     finish;
   - run the smoke: three steps per configuration, an exact-resume check, validation, merge and identity, measured
     times and peak GPU memory, and an extrapolated Stage B budget;
   - run one fresh A2.4 preflight, then the accepted runner's smoke on the smoke-merged direct model through the
     fine-tuned identity. This is mechanical only: no target is read and nothing is scored.
3. **Laptop:** build llama.cpp's `test-gbnf-validator` at b11277, and run the GBNF check on the corpus and every
   prepared label string.
4. **RTX PC:** the review archive.

**Stop.** ChatGPT reviews the label audit, the exact specification and the smoke evidence.

## 5. Stage B (after the review passes)

1. Fit seed 1 of each configuration, then merge it and run the runner smoke.
2. Run the continuation check. It is mechanical, never accuracy.
3. Fit seeds 2 and 3, then select and merge.
4. Run the nine development evaluations, then score, analyze and package.

Stage B stops only for a material validity failure, leakage, a label problem or a scope or budget change, and resumes
safely. Expensive inference is never rerun to repair a table or a date.

## Fix 1 (2026-10-12): the audit crash, and verified reuse of the prepared scans

Stage A's Part 2b prepared all 327 scans (305 in round 0, 22 in one reserve round). `prepare` then crashed while
building the audit sample (`KeyError: 'full_inventory'`). Commands quarantined before their view checks, such as a
disagreeing parsing label, have no view results, and the audit assumed every eligible command had them. Nothing was
published. The run folder `a24-20261012-032009`, with its specification and work folder, is kept.

Fix 1 has three parts:
- the audit shows those commands with their visible objects, marked not checked;
- the test fixture gains disagreeing labels, so this path is tested;
- `prepare --reuse-work` reuses each scan of an earlier work folder only if its own records prove it is what a fresh run
  would write (twelve checks per scan, `docs/a24-training.md`). A scan that fails any check stops the run.

In the tests, a verified reuse reproduces the fresh preparation's labels, cohorts, strata, rounds, examples and audit
exactly. Tampered copies (a derived scene, an audit output, an import, a recorded code hash, a missing stage) are
refused.

The runbook is `A2.4_runbook_fix1.md`. Stage A then continues at its Part 2c.

## The Stage A review, and fix 3 (2026-10-12)

ChatGPT reviewed Stage A's archive (`a24-20261012-032009-review.zip`, SHA-256
`4624555b4b6222f734c7e7197e79ebc7cac28bc6fafa047321a24f8bc5b59564`; brief in Claude Docs). It found Stage A
substantially correct and accepted every point put to it, recorded in D112. One correction was required. The audit's
`_visible()` read geometry under names the scene contract does not use, so all 1,554 object entries in the 143 audit
examples showed null centres and sizes. That blocked the evidence-support check the reviewer requires before training.

Fix 3 has three parts:
- `_visible()` reads `center_m`, `size_m` and `rotation_xyzw` exactly as recorded, at full precision, rounding for
  display only;
- `audit-export` re-exports the same 143 examples from the saved preparation and work records into a new folder. It adds
  the original derived scene and command records and their source annotation entries, deduplicated and linked by
  SHA-256. It records the preparation's identity and the superseded audit's hashes, and that the specification, cohorts,
  labels and six training-data files are unchanged;
- a focused regression check: known `center_m` and `size_m` values survive at full precision, and unknown values stay
  unknown.

Nothing else is repeated; the preparation, preflight, grammar check and smoke stand. The runbook is
`A2.4_runbook_fix3.md`. The corrected audit evidence goes back to ChatGPT; Stage B starts after that review.
