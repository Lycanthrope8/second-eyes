## 1. What was built

An offline, deterministic resolver for structured grounding queries (`docs/resolution.md`). It executes supplied
alternative readings over every object of one validated scene, through the accepted relation and direction
libraries, and returns one `resolution_run` record. It reads no English and no model output.

- **Schemas:** `schemas/grounding-query.v1.json`, `resolver-config.v1.json` and `grounding-result.v1.json`
  (JSON Schema 2020-12, closed records). The query schema copies the contract's `id`, `label`, revision and profile
  definitions unchanged.
- **Package `grounding/resolution/`:**
  - `validate.py`: options, configuration, query structure and graph, normalization, records through the accepted
    contract validator, D70's map rule, identities, and configuration loading;
  - `resolve.py`: evaluation, ranking, limits, caches, aggregation, provenance, trace, and the validated record;
  - `__main__.py`: the CLI;
  - `__init__.py`: exports `resolve`.
- **Tests:** `grounding/tests/test_resolution.py`, with fixtures and expectations in
  `grounding/tests/fixtures/resolution/` (see its `README.md`).
- **Records:** `docs/resolution.md`, this note, D71, and open questions O22 and O23. README rows were added, and the
  A2.1d note records the D70 correction's Windows acceptance.
- **Unchanged, byte for byte:** every accepted library, configuration, contract schema, serializer file, golden,
  audit and test. `HANDOVER.md` is also unchanged; it tracks A2 at plan level only.

### The D72 correction: integer representation of limits and rank k

**The defect.** After acceptance, ChatGPT reproduced two boundary failures:
- `max_rank_subset_evaluations: 10000.0` passed validation, then raised
  `AttributeError: 'float' object has no attribute 'bit_length'` at the rank preflight;
- a rank `k: 1.0` passed validation, then raised `TypeError: list indices must be integers or slices, not float`
  inside the accepted rank routine.

JSON Schema's integer type admits whole-valued floats, and the resolver had relied on it alone.

**The regression, written first.** 24 checks in a new section of `test_resolution.py`, outside the frozen
`cases.json` and `dispatch.json`. They are built from the frozen fixtures and query R15, with only the field under
test changed, plus two hand-derived queries: one with a rank on an anchor node, one with the ranked reading second.
They ran first against the delivered resolver, whose production files were byte-identical to the delivery:

| Run | Original checks | New checks |
|---|---|---|
| delivered resolver, jsonschema 4.26.0 | 153 of 153 | 6 pass, 18 fail |
| delivered resolver, jsonschema 4.0.1 | 153 of 153 | the same 6 pass, the same 18 fail |
| corrected resolver, both versions, direct and module-style | 153 of 153 | 24 of 24 |

The 18 failures before the fix:
- **All nine limits as whole floats:** eight requests completed with the float accepted, and
  `max_rank_subset_evaluations` raised the `AttributeError`.
- **`max_binding_attempts: 0.0`:** a `budget_exceeded` record carrying the float limit `0.0`.
- **A limit written `2e6`:** accepted.
- **`k: 1.0` on the root, on an anchor node and in the second interpretation:** each raised the `TypeError`.
- **Instrumentation:** with loaders, evaluators and rank made to raise, the float inputs reached them.
- **The CLI on real files holding `10000.0` and `1.0`:** exit 3 with a traceback and no `resolution.json`. The
  no-overwrite check therefore failed too: there was no file for it to protect.

The six checks that held:
- the integer-0 allowance;
- the integer controls for the ranked anchor (resolved `obj_003`) and for the later interpretation (ambiguous);
- the existing rejections of fractional, string and null limits;
- the existing rejections of fractional, string, null and out-of-range k;
- the CLI's valid R15 control (`obj_006`).

`test_resolution.py`'s SHA-256 was `6389ecb7150fb1e6e00d076c5165382abafb7fad9f0d40d04676f5e728f87d51` for the
before-fix run, and the after-fix run used the same file: no expectation was fitted to the correction.

**The fix,** in `grounding/resolution/validate.py` only. After structural validation passes, every field of
`limits`, and every non-null rank `k` in every QUERY interpretation, must satisfy `type(value) is int`. A failure is
`invalid_input` with no result and no budget:
- for a limit, `E_RESOLVER_CONFIG` at `$.limits.<name>`;
- for a rank, `E_QUERY_SCHEMA` at the original input path `$.interpretations[i].nodes[j].rank.k`.

The message reads "an integer value is required: 10000.0 is a float, and a float is not accepted even when it is
whole-valued". Nothing is converted, rounded or coerced, the ranges are unchanged, and no loader, evaluator or rank
call follows an invalid representation. `docs/resolution.md` and the two schemas' descriptions state the rule; the
schemas are otherwise unchanged.

**Incomplete fixes the new checks catch:**
- checking k in the first interpretation only: 2 checks fail;
- checking k on the root only: 2 fail;
- checking only the limit that crashed: 11 fail;
- coercing floats to integers instead of rejecting them: 17 fail.

**Unchanged:**
- `cases.json` and `dispatch.json`, byte for byte;
- every accepted library and suite: contract 70, relations 68, directions 115 and serializer 166, direct and
  module-style, under jsonschema 4.26.0 and 4.0.1;
- the fields the brief excludes. A whole-valued float in the query's `scene_revision` still passes, and the result
  echoes it as `0.0`; `schema_version: 1.0` still passes.

## 6. What failed and why

1. **The first full run passed 140 of 141.** Relation case 34, `near(obj_001, obj_002)` on two boxes, was never
   reached as an event. Both argument orders arise as the query forks. The brief's memo key sorts `near`'s
   arguments, so `near(obj_002, obj_001)` was called and traced first, and the case's order was served as a cache
   hit, which is never re-traced. The resolver was right, and the test's matching was too strict. The test now
   compares `near`'s arguments as a set, as it already compared `between`'s anchors, and `dispatch.json`'s rule
   sentence says so. The table's value, TRUE, was the value returned.
2. **The first cache-conflict check tested nothing.** It assumed R01 had filled the geometry cache, but R01 needs
   attributes only and never builds a relation evaluator. It was rewritten to fill a key with a `near` query first.
   The accepted cache's `ValueError` now propagates from the API, as the brief requires.
3. **Mutation testing found a check that didn't test its rule.** As first written, the check for "an UNKNOWN never
   ends a conjunction" put its UNKNOWN clause second: constraints run in canonical-JSON order, and `left` sorts
   before `right`, so the FALSE clause ran first. It was redesigned with `in_front_of`, which sorts before `left`,
   using hand-derived values: no_match, 6 calls and 2 cache hits. The mutant is now caught. The first trace
   violation removed only `emit()`'s own guard; that was equivalent, since every call site checks too, so the
   violation in the table removes both guards.
4. **One mutant crashed the suite instead of failing checks.** The case and invariant loops now report an exception
   as a failure.
5. **After Windows acceptance, ChatGPT reproduced two crashes on whole-valued floats:** a limit of `10000.0` and a rank
   `k` of `1.0`. Claude's error: the resolver relied on JSON Schema's integer type, which admits whole-valued floats.
   Its Boolean checks (V15, V39) passed only because that type excludes Booleans. Corrected by D72 (section 3).

## 9. Paper hooks

- **Method:**
  - a structured executor over complete alternative readings;
  - the three-valued AND and the fixed aggregation precedence;
  - conservative early termination at uncertain anchors;
  - a bounded rank preflight;
  - every limit checked before work, with technical failures kept apart from semantic outcomes.
- **Limitations:**
  - hand-authored queries resolving correctly is not English grounding accuracy;
  - supplied readings are not verified linguistic completeness;
  - Python work counts are not headset costs;
  - centre-distance ranking and the libraries' conditional geometry carry over.
