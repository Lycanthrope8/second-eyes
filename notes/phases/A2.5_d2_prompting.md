## 1. Scope (D98, D99)

On the headset, from a versioned annotated snapshot and a typed command, the app builds:

- the `coordinates_v2` document;
- the choices line, with stable inventory-based letters;
- the prompt.

All of it must be byte for byte what the PC builds. Golden PC references and fresh PC float32 references for these
interactive prompts are part of the delivery. Not part of it: caching, the interactive pipeline, ADB intake and the UI
(deliveries 3 and 4).

## 2. Design (D104, confirmed on 9 October; ChatGPT's review pending)

1. **Letters.** Letters follow the serialized object order: object IDs in ordinal order, as A2.3a's `choice_mapping`
   does. The list order is the same, and K is ASK, last.
   - The mapping depends only on the set of object IDs, never on the command, a target or a random stream.
   - Its identity is the SHA-256 of the TAB/LF mapping lines.
   - Letters do not persist across inventory changes; D99(6)'s invalidation applies.
2. **Pinned static text.**
   - One versioned prompt-asset file, generated on the PC, holds: the header and semantics lines (they depend only on
     the format and on `relations.v1` and `directions.v1`); the wrapper strings, system message and codes of the pilot
     protocol; the configs' hashes; and the serializer version.
   - The headset pins the file by SHA-256 and does not load the relation configs.
3. **Snapshots.** Annotated 3-, 6- and 10-object snapshots are chosen by a selection rule written in advance
   (hash-based, as in A2.3d). Provenance is recorded as the source scene's ID and revision and the source records'
   hashes.
4. **Validation.**
   - The PC validates snapshot and command records with the existing validators before export.
   - The headset verifies the files' hashes and builds documents, without re-implementing the validator.
   - Before any request is served, an on-device self-check rebuilds every shipped golden document and prompt and
     compares the bytes.
5. **Golden references.** For each snapshot and command:
   - the document and the prompt bytes;
   - the token IDs, from the pinned tokenizer;
   - the mapping and its hash;
   - the cache boundaries;
   - fresh float32 references under r006's protocol: revision `7ae5576…`, float32, eager attention.

   Dataset commands and written integration fixtures are labelled apart; the fixtures are implementation checks only.

## 3. Step 1: the C# prompt core

`quest-app/Assets/SecondEyes/Grounding/Prompting/PromptCore.cs` is plain C#, without Unity. It is committed unwired,
with its Unity `.meta` files written in advance, and contains:

- a strict JSON reader that keeps field order and each number's source text;
- `Canon`, which is `codec.enc` and `codec.number`. Non-integral floats are spelled as Python's `repr`: the shortest
  decimal that reads back exactly, the nearest such one, ties to an even digit. It is computed with exact integer
  arithmetic, so it does not depend on the runtime's number formatting;
- `Coordinates`, the objects, pose and command lines of `serializer.py`;
- `Choices`, the choices line, the serialized-order mapping and the prompt of `choices.py`.

**Verified in Claude's sandbox** (C# 9, .NET 8) against the Python functions themselves:

- 142,091 floats against `repr`, including every power of two and its neighbours, subnormals and extremes;
- 3,000 strings against `json.dumps(ensure_ascii=False)`;
- 806 documents and prompts against `serialize(..., format="coordinates_v2")` and `build_prompt`, equal down to the
  UTF-8 byte. They come from the contract fixtures and schema-valid variations: varied geometry and poses, unknown
  values, assumption-dependent fields, shuffled colour lists, and non-ASCII, quoted and tab-containing command text.
- Five deliberate bugs were each caught: the exponent threshold, the tie rule, the power-of-two gap, the candidate
  choice, and colour sorting.

The .NET harness is not part of the repository's suites.

**Limits, stated:**

- Object IDs and colours are sorted by UTF-16 code unit, while Python sorts by code point. These differ only for
  characters outside the Basic Multilingual Plane, which the records do not use.
- Number text is read by the runtime's `double.Parse`, assumed correctly rounded. Verified here on .NET 8; on the headset
  the golden self-check will verify it.

## 4. For ChatGPT's review

1. **The letter policy and A2.3d.** A2.3d randomized letters and list order to measure position effects. A fixed
   serialized-order mapping ties each object's letter to its ID order. Is that acceptable for the interactive pipeline,
   or should the order be inventory-based but not ID-sorted?
2. **The pinned prompt asset** in place of loading the relation configs on the headset.
3. **The snapshot source and selection rule**, and the provenance fields.
4. **The validation split:** the PC validates; the headset checks hashes and runs a byte-level self-check.
5. **The golden reference contents** and the two labelled command sets.
