## 1. What was built

The first A2.1 increment, offline only (D66): JSON Schemas for scene, command-context and category-map records
(`schemas/scene.v1.json`, `command-context.v1.json`, `category-map.v1.json`); a validator in Python
(`grounding/contract/validate.py` for parsing, record types, schemas and the command line; `checks.py` for the
semantic and cross-record rules); fixtures and a test (`grounding/tests/`); and the contract's description,
`docs/scene-contract.md`. No relations, resolver, serializer, adapter, training or headset code.

## 2. Final configuration

Schemas in JSON Schema 2020-12, checked by `jsonschema` (`jsonschema>=4.0`, added to `grounding/requirements.txt`).
Validation tolerance 1e-6 (`checks.TOLERANCE`), a v1 validation choice, not a relation threshold. No runs: this
increment measures nothing, so no run IDs.

## 6. What failed and why

Nothing failed in the acceptance run of `681caec`. Afterwards, ChatGPT reproduced two defects against the delivered
zip, both Claude's errors (`notes/failures.md`):

- A file holding only `null` passed, with exit code 0. `parse` used `None` to mean "parsing failed", which is also
  what JSON null parses to, so the record skipped every later check.
- `{"record_type": [], "schema_version": 1}` raised a `TypeError`: the record type and version were used as a lookup
  key before their types were checked, and a list can't be a key.

The correction reports a parsing failure through the issues list, and checks that `record_type` is a string and
`schema_version` an integer before the lookup; both cases now fail with `E_RECORD_TYPE`. Regression checks: the two
cases as invalid fixtures, 13 malformed record types built in memory, and the command line on the null file.

## 7. Deviations from the plan

Details the approved proposal left to the implementation, written down so they can be reviewed:

- Which source kinds may stand behind each evidence kind and unknown reason (the table in `docs/scene-contract.md`):
  in v1, `measured` has no permitted source and `inferred` may come from a dataset, fixture or prior table.
- A scene's identity is its ID, revision and evidence profile, so both profiles of one scene can be checked together.
- A referenced scene or map that isn't given produces a warning, `W_NOT_CROSS_CHECKED`, not an error.
- `quest_head` poses, reserved in the proposal, are rejected (`E_POSE_RESERVED`).
- Integers too large for a double count as non-finite, like NaN and Infinity.
- The fixture scene adds illustrative sizes, rotations, fronts, colours and an unmapped floor lamp to the a17 centres.
- Added: a README for the fixtures listing each invalid case and its one change, and test cases built in memory
  for dataset poses, a full rotation and an inferred value.
