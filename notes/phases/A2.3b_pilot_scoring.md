## 5. Decisions taken

D82. Implementation readings, recorded there: the format difference is augmented minus coordinates; source aliases
count every planned request and chosen aliases only scored ones; an empty-scene bypass would be unscored (unreachable,
since the target must be present); the command line always runs in pinned-sample mode, fixture mode exists only for
labelled tests, and rules and scores must share a mode; the summary and report derive from the published rows alone.

## 6. What failed and why

- First test run (implementation): the score command's own readback rejected its report, rendered from the in-memory
  summary in a different key order from the one a readback loads. It now renders in fixed orders from the canonical
  summary; nothing had been published or delivered.
- First test run (test): the "mismatched key" case changed one result's view, and the re-hashing helper then crashed in
  A2.3a's summary before the case reached its check. It now swaps two rows' formats; intent unchanged. Two checks were
  added after that run to prove the instrumentation is live. The expectations file is unchanged; the test file's hash
  at delivery is in the delivery listing.
- The sandbox could not build the Windows-equivalent bundle (above); a sandbox limit, not a project failure.
