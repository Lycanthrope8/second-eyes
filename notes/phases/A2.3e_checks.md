## 1. Input audit

The canaries show that the two logit paths agree, not that the prompt is right. `audit.py` (commit `4ae9c07`) exports and
checks the eight requests of the canary parents: r0001–r0004 (r0001's parent) and r0329–r0332 (r0330's, the longest
request for both models, chosen by the runs' own rule). For each request it records the exact prompt bytes, both
models' token IDs, the role boundaries in characters and tokens, the choices, the document hash and the command text.
It then checks:
- the prompt is exactly the system turn, the user turn and an open assistant turn, with the protocol's system message
  verbatim;
- the user turn is the choices line followed by the bundle's document byte for byte;
- the document lists the subscene's objects and carries the derived command's exact text;
- the letters are A..J for the objects, each object once, and K is last and always means ASK;
- the mapping equals the frozen policy's;
- the prompt is fully rebuilt from the protocol, the mapping and the document, with no annotation ID, target field or
  rules outcome (those files are never opened);
- each tokenizer re-creates the frozen token IDs, every role boundary is a token boundary, every letter is one token,
  and the scored position is the last token of the open assistant turn.

**Laptop run (7 October 2026, Python 3.11.9).** `C:\Users\jubay\second-eyes-data\iref-compare\input-audit-20261007-171707`:
8 requests, 128 checks, none failed. Manifest `150bd6f17702564fd3839896d18120178321f9311302805df19ad9c03174842b`;
`audit.json` `0c59a791…`; linked to requests `0e49a9f6…` and to both pinned tokenizers. No defect was found, so A2.3d's
results stand unchanged.

## 2. Costs

`costs.py`. From the existing artifacts: tokens per model, view and format with the paired difference; uncached forward
timings, main-run load times and peak memory of r006 and r007. Measured on the laptop: 16 parent/view cases chosen by
SHA-256 of UTF-8(`second-eyes/a23e/cases/v1` + LF + parent + LF + view), both formats, one warm-up and five
repetitions. Each stage is timed separately:
- relation construction, by wrapping the serializer's relation-table builders from outside, with the code unchanged;
- the rest of serialization;
- prompt assembly;
- tokenization per tokenizer.

Disk reads and validation are timed apart. Nothing is reported unless every rebuilt document, prompt and token list
equals the frozen one.

**Sandbox rehearsal** (Linux reconstruction, labelled, not a result): 16 cases; every reconstruction matched; readback
clean.

## 3. Cache check

`cache.py`, the 0.5B on the same 16 cases, on the RTX PC. It adds a prefill and a cached-suffix path to A2.3a's
unchanged TorchModel, cropping the KV cache back to the prefix after each use. Each request is compared, uncached
against cached, under:
- a repeated identical request (all tokens but the last);
- the other format of the same parent and view;
- another parent's request;
- three edited copies (scene evidence, pose, choices), each allowed to reuse only the tokens before the edit.

Identity changes (model or tokenizer) get no reuse. Tested with labelled doubles, including a cache that drops its
prefix, which fails D56 as it should.
- **Reuse:** only exactly matching token prefixes, reported separately for repeated identical requests and across
  different commands.
- **Criteria:** D56: the same best candidate, the same order among candidates with at least 1% restricted share, and
  a total variation distance of at most 0.05.
- **Invalidation:** checked on changes of scene evidence, pose, choices, format, tokenizer and model.
