## 1. What was built

Offline only (D68): `grounding/relations/directions.py`, which provides `left`, `right`, `in_front_of` and
`behind` in the `user_heading`, `user_to_anchor` and `object_intrinsic` frames, chosen by the caller. It comes with:
- an immutable provisional configuration, `directions.v1.json`, in the format `schemas/direction-config.v1.json`;
- record-scoped field provenance in each result;
- the brief's fixed cases with contract-valid fixtures (`grounding/tests/fixtures/directions/`);
- the test `grounding/tests/test_directions.py`;
- `docs/directions.md`.

Not included: A2.1b's code and tests, which are unchanged; a resolver, serializer, adapter, training, or Unity, C#
or headset code.

## 6. What failed and why

Nothing in the acceptance run of `2dec57e`. Afterwards, ChatGPT reproduced a package-import defect, which is Claude's
error (`notes/failures.md`).

**The defect.** `directions.py` inserted its own directory into the import path and imported `predicates` by its
bare name. Imported through the package, `grounding.relations.directions` therefore loaded a second copy of the
module, with a second `Truth`, so a directional TRUE wasn't the package's TRUE. For example, `P.AND(directional
TRUE, P.TRUE)` returned UNKNOWN. `predicates.py` imported `geometry` the same way. The suites missed it because
their own path changes imported every module by its bare name, so there was only ever one copy.

**The correction.** Relative imports: `from . import predicates as P` in `directions.py` and `from . import geometry
as g` in `predicates.py`, with no import-path changes in either module. The two relation test scripts now import
through `grounding.relations` and add only the repository root. `Truth`, its members, `AND` and `OR` stay defined
once, in `predicates.py`. No relation mathematics, threshold, configuration, fixture, result contract or expected
answer changed, and the contract validator and its test are untouched.

## 7. Deviations from the plan

None from the brief. Routine details it left open:
- When evidence is missing and a frame is also degenerate, both reasons are listed. The value is UNKNOWN with no
  score either way.
- The viewer–anchor separation or the front's horizontal norm is reported whenever it could be computed, including
  in degenerate and missing-evidence cases.
- A record passed in the wrong role raises a `ValueError`: a scene as a command, or a command as a scene.
- Configuration numbers that overflow a float fail to load, like NaN.
- The strict parser is A2.1b's own, reused unchanged.
