## 1. What was built

- `docs/iref-vla-model-inputs.md`.

## 2. Final configuration

Policy `iref_model_inputs.v1`; source policy `iref_category_complete.v1`; formats `coordinates_v2` and
`coordinates_relations_v2`; object limit 10; relation work allowance 1,190 slots (`work_slots(10)`); input-only ceilings
1,024, 2,048 and 4,096 tokens, equality passing; libraries `relations.v1@d922fe902669` and `directions.v1@73590e939d4f`;
Qwen/Qwen2.5-0.5B-Instruct tokenizer at revision `7ae557604adf67be50417f59c2c2f167def9a775` with the three pinned file
hashes, transformers 4.57.6 and tokenizers 0.22.2 (`Qwen2TokenizerFast`); the accepted sizing wrapper and system message.
Label: exact for the pinned Hugging Face tokenizer and this sizing wrapper; deployed-GGUF execution parity not established by this increment.

## 7. Deviations from the plan

None from the brief's decisions. `run_preparation` takes `tokenizer` and `work_cap` for fixture tests only; the CLI has
neither, so it always loads the pinned tokenizer, runs calibration and uses 1,190 slots.

## 9. Paper hooks

- **Method:** answer-independent materialization of category-complete selections; exact pinned-tokenizer sizing with
  ID-level prefix reuse and telescoping block attribution.
- **Results:** input lengths of both formats against declared ceilings, as development measurements from one room.
- **Limitations:** the summary's list, including no deployed-tokenizer parity and no Quest measurement.

## Addendum, 6 October 2026: Windows acceptance and cross-machine reproducibility

**Acceptance (5 October 2026, on the project lead's laptop).** Preparation unit-only checks 53 direct and 53
module-style; the serializer suite 167; the sub-scene unit suite 73; published-bundle acceptance (`--bundle`) 64. The
preparation took 725 s and produced 199 scenes, 2,099 derived commands, 4,198 documents and 7,744 measurement rows, with
no relation-work failure. Its summary and report match the sandbox's byte for byte. The bundle is
`second-eyes-data\iref-model-inputs\a22d-20261005-153413`: index `44a994b4…`, measurements `30769ca9…`, summary
`46a82660…`, report `e8710888…`, category map `7e749963…`.

**What differs, and why (ChatGPT's review of the Windows evidence, A2.3a brief).** The index, measurements and folder
aggregates differ from the sandbox's. A fresh Linux conversion with the accepted adapter and pinned source files differs
from the Windows scene at exactly three values: obj_021 quaternion z (Linux -0.7195784578738584, Windows
-0.7195784578738583), obj_029 w (0.7214488408602325, 0.7214488408602324) and obj_060 z (0.7501103317024724,
0.7501103317024725), each about 1.11e-16 apart. That is consistent with cross-platform floating-point differences; the
exact mechanism was not isolated. The D77 parent hashes are `23a612e2…` (Linux) and `b97dd0bf…` (Windows), and
recomputing the derived identities and records from the Linux scene reproduces the sandbox's index (`69db7f9f…`) and
scene (`03ac2d8a…`) and command (`f353ab26…`) aggregates exactly; those aggregates include file names. In four targeted
renders (both formats for one selection containing obj_029 and one containing obj_060) the Windows document hashes were
reproduced, and the Linux geometry changed only the objects line; obj_021 is in no fitting selection. That targeted
check does not establish equality of every relation result or model prediction across platforms. The commands agree
(`d720729c…` on both), and two Windows runs gave byte-identical indexes.

**Consequence.** No production defect is shown and nothing is patched: no rounding, no change to canonical hashing, no
rewritten manifest. The accepted Windows bundle is the frozen input of A2.3a (D81); another machine copies its bytes
rather than regenerating them.

**Correction to the delivered acceptance instructions.** They expected the preparation to fail in the ordinary
environment. It passed, correctly: the code checks the installed packages and the tokenizer files, not an environment's
name, and that environment has the pinned versions. The resulting second bundle (`a22d-20261005-153413-noenv`) is valid
and is kept unchanged; its index matched the first Windows run's, showing same-platform determinism.

**Baseline.** On 5 October the sandbox's reconstruction of `c5b7704` was compared with the public repository: 517 files,
identical apart from line endings. `docs/README.md` had no entry for `docs/iref-vla-model-inputs.md`; A2.3a adds it.
