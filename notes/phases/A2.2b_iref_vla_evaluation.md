## 1. What was built

- **`grounding/evaluation/iref_vla/`:**
  - `parse.py`: the sample grammar, using text and vocabularies only.
  - `predict.py`: views, derived records, queries, resolution, the summary, the manifest, publishing and validated
    loading. It takes no annotation argument.
  - `score.py`: reference checks, scores, the summary, the report and the scoring manifest.
  - `protocol.py`, with the tracked `protocol.v1.json`.
  - `output.py`: atomic publishing.
  - `__main__.py`: the `predict` and `score` commands.
- **The schema:** `schemas/iref-evaluation.v1.json`, closed records for the protocol, parses, predictions and scores.
- **Tests:** `grounding/tests/test_iref_vla_evaluation.py`, with `grounding/tests/fixtures/iref_vla_evaluation/`:
  - the expectations;
  - the hand-authored scenes F0, F1, F0_tie, F0_desk and a scoring scene;
  - their map, view manifests and commands;
  - the scoring annotation bundle.
- **Records:**
  - `docs/iref-vla-evaluation.md`;
  - D75, which also records A2.2a's acceptance at `4d847ee` and the clarified volume wording;
  - the README rows;
  - three limitations entries.

No accepted module changed: the contract, relation libraries, resolver, serializer and adapter are byte-identical to
`4d847ee`.

### Mutation testing

Thirteen deliberate violations of brief rules, each alone on a scratch copy, were all caught by the unit suite:
- preferring the first lexical reading (P35, P37, P38);
- dropping size words silently (11 checks, P14 and onwards);
- case folding (P23) and trimming (P25);
- skipping the plural form (P19–P21);
- trusting the view manifest (all six tamper cases);
- keeping timings in the semantic hash (the fresh-process hash, among others);
- stripping all diagnostics from the hash (the work-count check);
- counting an ambiguous result that lists the target as correct (the C counts);
- a numeric 0 for an empty denominator;
- accepting contradictory targets;
- keeping scene objects in input order (the reordering check);
- ordering records by execution (the reverse-order check).

## 6. What failed and why

1. **An unused import in the frozen test.** Lint found it right after the first hash record, before any implementation;

2. **Defects caught on rereading, before the first run.**
   - My first draft of the parse-record check would have accepted an ambiguous parse with a count of 1.
   - The runner draft had an unused import, a function-level private import, and no guard against a non-object line
     in `parses.jsonl`.

   All were corrected before the first run; no frozen expectation changed.
3. **Sandbox process limits, not product failures.** The first background sample run ended with the assistant's turn,
   and one launch used a `/usr/bin/time` that isn't installed. Both runs were repeated in full.

## 7. Deviations from the plan

None from the protocol. These choices were made where the brief was silent, each recorded in D75 and
`docs/iref-vla-evaluation.md`:
- non-string text is a `TypeError`, and empty text a `ValueError`;
- derived view scenes list objects in object-ID order;
- the parent link is recorded in `parses.jsonl` and `predictions.jsonl`;
- selection changes are reported as four counts;
- the plural tail is any nonempty text;
- input hashes are file bytes from the command line, and canonical JSON from the API;
- the evaluation has its own `E_EVAL_*` codes;
- only annotated scenes are evaluated, and command folders hold only `<command_id>.json` files.

## 11. Validation correction (D76)

ChatGPT's review found implementation defects in the evaluation's input-consistency checks. None changed a stored
prediction:
- **The text cross-check:** a parse record's text wasn't checked against its command contexts, so scoring accepted a
  changed parse text. The semantic hash doesn't cover parse records.
- **Acceptance gaps:** an extra, otherwise valid command context and a prediction manifest of version 99 were accepted.
- **Crashes instead of structured errors:**
  - null, scalar or list records in the contexts or predictions;
  - a null or scalar summary;
  - malformed manifest fields (resolver, views, library identities);
  - malformed inventory-view IDs and object IDs.

  Each raised AttributeError or TypeError.
- **A wrong exit code:** a null or list scene file, or a scalar map file, made the prediction command line exit 3
  instead of 2.

**The correction, in `predict.py` only:**
- shapes are checked before access, for the inputs, the inventory views and the readback;
- each parent must have exactly one context per view, with none extra, missing or duplicated;
- each context's text must equal its parse text exactly;
- a new evaluation record's version must be the integer 1.

`parse.py`, `score.py`, the protocol, the schemas, the libraries, the fixtures and the expectations are unchanged.
Scoring still never reruns parsing or resolution.

**Evidence:**
- **The regressions:** 42 checks were frozen before the fix (test SHA-256 `e6d1505a2ae32ca32d0190158c596f39a6a3d0813be5d7d63fa147a3a586f5fb`,
  2026-10-05T06:31:01Z; the original pre-implementation hash stays in section 3). Against the delivered code, 26
  failed and 16 already passed. After the fix, the unit-only suite passes 197 of 197 (155 original and 42 new),
  direct and module-style, under jsonschema 4.26.0 and 4.0.1.
- **Unchanged results:**
  - every fixture's semantic prediction hash, and the reviewed scoring summary and scores, are identical before and

  - rescoring the sandbox's sample predictions with the corrected code gives byte-identical `scores.jsonl`,

  - only the scoring manifest's code hashes change.
- **Windows acceptance of the correction:** the project lead's run passed.

  - Rescoring the existing Windows predictions into a fresh folder gave `scores.jsonl`, `summary.json` and
