# A2.7: the deployment candidate's export and Quest verification (D115)

A2.7 puts the fine-tuned parser with the accepted resolver on the headset and checks that it behaves there exactly as
on the PC. The scope is parser-only (D115): Paper 1 is an HDI paper, so A2.7 builds, checks and measures only the
deployed path. Nothing is retrained; A2.4 stays closed.

## The candidate

| | |
|---|---|
| System | The fine-tuned parser + the accepted resolver |
| Model | `a24.parser.s1`, its selected checkpoint (epoch 2) |
| Design | Chosen on development evidence (A2.4, D114) |
| Seed | The best inner-validation score, ties to the lowest seed index: seed 1, 363 of 363 rows |

The seed rule keeps each fit's checkpoint as the frozen rule selected it and chooses among seeds by the same
inner-validation score. It was adopted after the pilot and before export. The three-seed results remain the pilot's
main comparison.

**Scope amendment.** The direct model's export and headset runs, and the rule parser's port and headset runs, are
dropped. The existing desktop comparisons (A2.6, A2.4) are preserved. No Quest cost is measured for comparing the
three designs: that gives up comparative headset-cost evidence the intended HDI claims don't need.

## How it runs

Each command starts from an empty cache: the whole prompt is evaluated with keep 0, then greedy constrained decoding
runs one token at a time, each step reusing the cache within this request only. Nothing is reused across requests
(D105). This is how the accepted Python parser decodes too.

Constrained decoding uses llama.cpp's own grammar sampler inside `libse_llama` (new functions `se_grammar_*` and
`se_decode_constrained`):
- the output ends only with `<|im_end|>`; Qwen's other end-of-generation tokens are never allowed;
- the greedy choice is the highest allowed logit, ties to the lowest token ID;
- it is found by applying the grammar to growing slices of the vocabulary ranked by logit, which gives exactly the
  full-vocabulary answer: one full-vocabulary application costs about a second (1.4 s in Delivery 1's sandbox), so the
  full check serves only verification.

## Acceptance criteria, frozen before any result (D115)

The numbering is the plan's; criteria 3 and 8 belonged to the dropped comparators.

**Port correctness** (exact: a difference is a defect to fix, never a tolerance):
1. The resolver, relation library and query validator on the headset reproduce Python's status, candidate set and
   target on every frozen resolution, unresolved cases included.
2. The language reader and query conversion on the headset produce Python's queries from every parser output and from
   the grammar's 97-string corpus.
3. *(Dropped with the rule parser's port.)*
4. Constrained decoding matches the Python decoder:
   - **desktop:** the allowed tokens at every distinct prefix of the 2,715 reference decodes and at the 21 frozen
     prefixes;
   - **headset:** at the 21 frozen prefixes and at every step of the frozen 20-command mask sample. Amended before
     freezing: a full-vocabulary check at every step of 300 commands would take hours on the headset;
   - the end token allowed exactly when the output is complete; ties to the lowest token ID; the outcomes completed,
     length exhausted and empty allowed set.
5. Technical failures stay distinct from declines and from ASK, on every path.
6. The grammar-enabled native library has its own build identity, verified on the headset as under D102.

**Model agreement** (the exported Q8_0 against the float32 reference):

7. **Desktop:** at least 99% of the 2,715 commands decode to exactly the float32 reference's tokens and status; every
   difference is listed beside both outputs and both views' outcomes; a technical failure is never agreement.
   **Headset:** the frozen 300-command subset decodes to exactly the desktop Q8_0's tokens; any difference is
   investigated as a platform difference.
8. *(Dropped with the direct comparator.)*
9. No candidate's acceptance closes the base model's historical numerical discrepancy (D105), which stays recorded as
   unresolved.

**The frozen sets.** The 300-command headset subset takes the development parents only, stratified by relation: at
least 10 per relation, the other 200 in proportion to what is left of each (largest remainder, ties by name). Within a
relation, parents are ranked by SHA-256 of `a27.headset-subset.v1|<parent ID>`. The mask sample is the first 2 of each
relation's chosen parents. Only IDs and relations are used, never an outcome.

## Measured, not judged

For the deployed path on the headset, over A2.5's 3-, 6- and 10-object snapshots: the time from typed submission to a
validated target or a decline, cold and warm (median and 90th percentile); prompt and generated tokens; peak memory;
MR frame behaviour. No new soak. A2.5's direct-path figures are history for the base model.

## Deliveries

1. **Delivery 1, desktop (PC and laptop):** the grammar-enabled native library with its tests; the export to GGUF Q8_0
   (`python -m grounding.a27 export`); the bundle with the frozen subset (`bundle`); the desktop run on the laptop's
   host build (`desktop`: criterion 4's and 7's desktop halves); the comparison on the RTX PC (`compare`). Review.
2. **Delivery 2, code:** the resolver, relation library, query validator and language reader in C#, with Unity
   edit-mode tests against the PC's golden outputs (criteria 1, 2, 5); the headset pipeline and replay; the Android
   build and its identity (criterion 6).
3. **Delivery 3, headset:** the replay acceptance (criteria 4 and 7 on the headset) and the measurements. Review, then
   A2.7's closure.
